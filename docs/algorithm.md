# 训练算法设计

本文说明两个任务各自的奖励函数、策略/价值网络结构，以及 PPO 一整个迭代里「采集 → 计算优势 → 更新网络」的完整流程：

- **静态站立任务**（`Isaac-M20-Wheeled-v0`）：把速度指令固定为零，即"站稳"。§1–§5 以它为主线。
- **速度指令任务**（`Isaac-M20-Wheeled-Velocity-v0`）：跟踪 `(vx, vy, ωz)`，6 阶段课程 + 阶段间续训，见 [§6](#6-速度指令任务-m20-第一版正式配置)。

配置入口：

- 奖励权重与观测/动作：`tasks/m20_env_cfg.py`（站立）、`tasks/m20_velocity_env_cfg.py`（速度指令）
- 奖励公式：`tasks/rewards.py`；观测项与指令采样：`tasks/observations.py`、`tasks/commands.py`
- 网络与 PPO 超参：`tasks/agents/rsl_rl_ppo_cfg.py`
- 课程与续训：`scripts/train.py`；验收测试：`scripts/eval.py`

## 1. 奖励函数（站立任务）

采用 legged_gym（Rudin et al., *Learning to Walk in Minutes*）与 IsaacLab `AnymalC` 任务的标准奖励集，把速度指令固定为零，即"站稳"。

**符号约定**：惩罚项的函数返回**正量纲值**，符号由权重携带——与 `isaaclab.envs.mdp` 一致（例如 `lin_vel_z_l2` 返回 `v_z²`，配置里给权重 −2.0）。所以下表「公式」列写的都是函数返回值，`rewards.py` 里不出现前导负号。函数返回负值 × 负权重 = 正奖励，会把惩罚项变成激励。

| 分项 | 权重 | 函数返回 | 含义 |
| --- | --- | --- | --- |
| `track_lin_vel_xy` | **+1.5** | `exp(-‖v_xy‖² / 0.25)` | 线速度跟踪核，指令为 0 → 越静止越接近 1 |
| `track_ang_vel_z` | **+0.75** | `exp(-ω_z² / 0.25)` | 偏航角速度跟踪核，指令为 0 |
| `track_wheel_vel` | **+0.5** | `exp(-‖ω_wheel‖² / 2.0²)` | 四个轮子静止（轮腿机器人专属） |
| `lin_vel_z` | −2.0 | `v_z²` | 禁止上下颠簸 |
| `ang_vel_xy` | −0.05 | `Σ ω_xy²` | 禁止翻滚/俯仰角速度 |
| `flat_orientation` | −2.5 | `gx² + gy²` | 机身水平（`g` 为重力在机体系的投影） |
| `base_height` | **−20.0** | `(h − 0.50)²` | 基座高度二次惩罚（论文用的是二次型，不是 exp 奖励） |
| `joint_deviation` | −0.5 | `Σ_legs abs(q − q_default)` | **仅 12 个腿关节**偏离默认站立姿态（legged_gym 的 `stand_still`） |
| `joint_vel` | −1e-4 | `Σ q̇²` | 关节速度正则 |
| `joint_acc` | −2.5e-7 | `Σ q̈²` | 关节加速度正则，抑制高频抖动 |
| `joint_torques` | −1e-5 | `Σ τ²` | 省力矩 |
| `action_rate` | −0.01 | `Σ(aₜ − aₜ₋₁)²` | 动作平滑 |
| `termination_penalty` | **−200** | `1[非超时终止]` | 摔倒的重大惩罚 |
| `alive` | +0.15 | `1` | 存活奖励 |

**`termination_penalty` 是最关键的一项**。缺少它时，摔倒的代价接近零，而 `action_rate` / `joint_torques` 等正则项是每步累积的——于是"尽快摔倒结束回合"反而收益更高，策略会主动学怎么更快结束（表现为 episode length 持续下降）。论文里这一项通常是 −200 到 −400。

**`base_height` 必须是二次惩罚**：权重 −20 作用在 `(h−h*)²` 上。换成 `exp` 奖励形式时，远离目标高度的区域梯度几乎为零，等于没有推力。

**轮组的两个专门处理**（轮腿机器人区别于普通四足的地方）：

1. `track_wheel_vel` 用 exp 核把四个轮速压到零。不能用 L2：`joint_vel` 是 −1e-4 的量级，而轮速量纲是 rad/s，ω ≈ 1 rad/s 时贡献只有 −4e-4，**零速附近的梯度几乎是死的**；exp 核在原点梯度非零且有界。σ_w = 2.0 rad/s 吸收了四个轮子的求和。
2. `joint_deviation` **只算 12 个腿关节**。轮子的绝对角度是无界的（`continuous` revolute，不 wrap），转两圈就是 4π → 每步罚 6.3，能把整套奖励淹没。轮子的"别动"由 `track_wheel_vel` 负责，不用关节角。

**终止条件**（触发即本回合结束、重置）：

- `base_height`：基座高度 < 0.25 m（趴下）
- `bad_orientation`：倾角 > 0.7 rad（翻倒）
- `time_out`：满 10 s（50 Hz × 200 步）

注意实现里站立任务的 `termination_penalty` 已经从 `mdp.is_terminated` 换成了 `rewards.fall_terminated`（只罚真摔倒、超时归零），但站立任务**没有**每步 0 下限，所以它仍然保留 −200 的量级：删掉终端惩罚会让"早摔"重新变便宜。速度指令任务用 −10，并且由 env 直接加（见 §6.3）。

## 2. 网络设计

rsl_rl 的 Actor-Critic，两个 MLP 共享同一份观测输入（`obs_groups` 里 actor 和 critic 都吃 `policy` 组）。

**站立任务**：

```text
观测 o ∈ R^57
  │
  ├─ Actor  (策略)    57 → 512 → 256 → 128 → μ∈R^16
  │                     ELU    ELU    ELU    (对角高斯, init σ=1.0)
  │
  └─ Critic (价值)    57 → 512 → 256 → 128 → V∈R^1
                        ELU    ELU    ELU
```

**速度指令任务**（`M20VelocityRslRlPpoRunnerCfg`）：

```text
观测 o ∈ R^56
  │
  ├─ Actor  (策略)    56 → 256 → 256 → μ∈R^16    ELU, 对角高斯 init σ=0.5
  └─ Critic (价值)    56 → 256 → 256 → V∈R^1     ELU
```

- **站立观测 57 维**：`base_lin_vel(3) + base_ang_vel(3) + projected_gravity(3) + joint_pos(16) + joint_vel(16) + last_action(16)`。
- **速度指令观测 56 维**：见 §6.1，多 3 维指令、少 4 维（腿/轮关节拆开算）。
- **动作 16 维** ∈ [-1,1]，都是**目标值**，不是力矩：
  - 腿 12 维：`q* = q_default + a × 0.25 rad`（`JointPositionActionCfg`）
  - 轮 4 维：`ω* = a × scale`（`JointVelocityActionCfg`）；站立 `scale=20`，速度指令任务 `scale=8.0`
- **PD 伺服环**（`ImplicitActuatorCfg`）在 200 Hz 物理步上把目标跟踪成力矩：腿 kp=80、kd=2，轮 kp=0、kd=2（速度伺服），力矩上限 76.4 / 21.6 N·m。策略负责决策，PD 只负责跟踪。
- **激活** ELU；**无观测归一化**（`actor_obs_normalization=False`）。
- **策略头**：输出均值，方差固定为 `init_noise_std` 的对角高斯（不学方差），采样得到动作。

站立任务关键超参（`RslRlPpoAlgorithmCfg`）：γ=0.99、λ(GAE)=0.95、clip=0.2、熵系数 0.01、价值损失系数 1.0、`num_learning_epochs=5`、`num_mini_batches=4`、lr=1e-3（`schedule="adaptive"`，KL 超 0.01 就降 lr）、`max_grad_norm=1.0`。速度指令任务的超参见 §6.5。

## 3. 运行与更新流程

**时间尺度**：物理 200 Hz（`sim.dt=0.005`），策略 50 Hz（`decimation=4`，每 4 个物理步出一次动作）。站立回合 10 s = 200 个策略步，速度指令回合 20 s = 1000 个策略步。

**一次 PPO 迭代**：

1. **采集**：N 个并行环境各推 `num_steps_per_env=24` 步，得到 N × 24 条 (oₜ, aₜ, rₜ, oₜ₊₁, done) 样本（两个任务默认都是 N=4096 → 98,304）。
2. **算优势**：Critic 给出每步 `V(o)`，用 GAE（γ=0.99、λ=0.95）沿时间反向算优势 `Âₜ`，回报 `Rₜ = Âₜ + V(oₜ)` 作为价值回归目标。
3. **多轮更新**：把样本打乱分成 minibatch，循环 `num_learning_epochs` 遍，每遍对 Actor 和 Critic 各做一次梯度下降：
   - **Critic**：`loss_V = 0.5·(V − R)²`（价值损失系数 1.0）；
   - **Actor**：PPO-clip 目标 `min(rₜ·Â, clip(rₜ, 1±0.2)·Â) + entropy_coef·熵`，`rₜ = π(a|o)/π_old(a|o)`；
   - 梯度范数裁剪到 1.0。
4. **自适应学习率**：每遍后若新旧策略 KL 超过 `desired_kl`，lr 自动下调。
5. 清空 buffer，用更新后的策略进入下一轮采集。

**训练总量**：站立 `max_iterations=3000` 轮，每 `save_interval=100` 轮存一个 `model_*.pt`；速度指令任务分 4 阶段共 3250 轮，详见 §6.6。

**为什么直驱力矩开局会大面积趴下**：没有 PD 兜底，随机初始化的策略输出的是乱力矩，机器人生成就倒。这属正常——`base_height`/`flat_orientation` 的信号会把策略逐步拉向"撑住"的力矩组合，通常几百轮内趴下率开始下降。

## 4. 域随机化

站立任务在 `tasks/m20_env_cfg.py` 的 `EventCfg` 里全开；**速度指令任务第一版默认关闭**（见 §6.7），只保留重置时的小扰动。

`startup` 类在场景建立时抽一次，`reset` 类在**每个环境每次重置时重新抽**——策略面对的不是一台机器人，而是一族机器人。

| 项 | 模式 | 范围 | 目的 |
| --- | --- | --- | --- |
| `physics_material` | startup | 静/动摩擦 0.5–1.25，restitution 0 | 地面/轮子材质差异 |
| `reset_base` | reset | xy ±0.10 m，z 0–0.04 m，roll/pitch ±0.10 rad，yaw ±0.30 rad；线速度 ±0.1 m/s | 初始姿态偏差 |
| `reset_joints` | reset | **腿关节** ±0.15 rad，速度 ±0.5 rad/s | 编码器/标定的初始误差 |
| `reset_wheels` | reset | 轮关节角度归零（无偏移） | 连续关节角度会跨回合累加，必须清零 |
| `base_mass` | startup | 机身质量 **+(-2.0, +3.0) kg**（叠加），重算惯量 | 载荷变化（相机、电池、雷达） |
| `base_com` | startup | 质心 x/y ±0.03 m，z ±0.02 m | 载荷不在几何中心 |
| `push_robot` | interval | 每 4–8 s 给 x/y 一个 ±0.5 m/s 的瞬时速度 | 外力扰动、抗推 |

### 课程调度

站立任务上表写的是**满幅范围**，实际生效的是 `满幅 × level`，`level ∈ [0, 1]`（`tasks/dr.py`）：

```text
level = clamp(iteration / (max_iterations × --dr_ramp), 0, 1)
```

默认 `--dr_ramp 0.4`，3000 轮就是**前 1200 轮从 0 线性爬满**，之后固定 1.0。`level = 0` 时等价于完全没有随机化的基线。

为什么要有这条：满幅 DR 从第 0 轮开满，策略还没学会站稳就被随机质量和推力反复打断，表现就是**存活率先升后降**——它学到的那点站立能力被越来越难的扰动抹掉，而它又还没强到能适应。课程把任务始终放在"略高于当前能力"的区间里。

注意 `reset_wheels` **不参与课程**（它用 `mdp.` 而不是 `dr.`），因为它不是随机化，是每回合必须执行的清零。质量和质心是 `startup` 项，抽一次就固定，也不参与课程。

几点设计取舍：

- **质量和质心必须是 `startup`**。IsaacLab 的 `randomize_rigid_body_mass` / `randomize_rigid_body_com` 是「读出当前值再加偏移」，不是「在默认值上重算」。放在 `mode="reset"` 里的话，一个回合结束再加一次，一个环境训练中重置几百次，质量就累加几百份——晚期整批机器人重到站不起来，**表现正是存活率先升后降**。`startup` 只在建场景时抽一次，但抽样是按环境独立的，4096 个环境依然构成一个质量分布。
- **推力用速度脉冲**（`push_by_setting_velocity`）而不是持续外力：真机上人推一把、撞一下，都是在几十毫秒内改变动量，速度突变更接近这个物理过程，实现也更便宜。
- **轮子不参与 `reset_joints`**。轮子是连续关节，初始角度没有物理意义。
- **策略观测里没有质量/质心**，所以它只能学一个"对这一族参数都稳"的策略，这正是 sim2real 需要的。

如果加了 DR 之后训练曲线开始抖或跌，**先降 `push_robot` 的幅度**（±0.5 → ±0.3 m/s），它对回报的冲击最直接；其次是 `base_mass` 的上界。

## 5. 看板指标

| 指标 | 期望趋势 |
| --- | --- |
| `Episode_Reward/base_height` | 往 1 爬（高度到位） |
| `Episode_Reward/flat_orientation` | 往 0 收（越平越好，本就是负分） |
| `Episode_Reward/base_motion` | 往 0 收（不再漂移） |
| `Episode_Termination/base_height` / `bad_orientation` | 从 ~100% 往 0 降 |

加了域随机化之后，`Episode_Reward/*` 的绝对值会整体下降，这是**正常的**——同样的策略在更难的初始条件下拿不到那么多分。看趋势而不是绝对值。

## 6. 速度指令任务（M20 第一版正式配置）

`Isaac-M20-Wheeled-Velocity-v0`，配置在 `tasks/m20_velocity_env_cfg.py`。它是**独立注册的第二个任务**：站立任务一字未改，两者各自训练、各自出 checkpoint。

**为什么必须是两个任务**：观测维度不同（57 vs 56），Actor 第一层的输入矩阵形状不同，两边的 `model_*.pt` 不能互换；日志也分开放（`logs/rsl_rl/m20_wheeled/` vs `logs/rsl_rl/m20_velocity/`）。

**旧站立模型也不能直接续训速度任务**——观测维度不同，连前 6 维的顺序都不同（站立把线速度放前面，速度任务把角速度放前面），所以连"截断 + 补齐"都救不了。它的能力改由课程的阶段 1（零指令站稳）重新建立：见 §6.6。

### 6.1 观测（56 维）

| 观测量 | 维度 | 说明 |
| --- | --- | --- |
| 机身角速度 | 3 | IMU，机体系 |
| 投影重力 | 3 | 姿态信息 |
| 机身线速度 | 3 | X、Y、Z，机体系 |
| 腿部关节位置偏差 | 12 | 相对默认位置（`mdp.joint_pos_rel`） |
| 腿部关节速度 | 12 | 关节运动状态 |
| 车轮角速度 | 4 | 四个轮子（`mdp.joint_vel_rel`） |
| 速度指令 | 3 | 前后、左右、偏航 |
| 上一时刻动作 | 16 | 动作连续性 |
| **总计** | **56** | Actor 输入 |

两条容易错的细节：

- **线速度和指令都在机体系**。训练、播放、部署三处必须同一个坐标系，混用世界系会让策略在某些朝向下突然失灵。
- **指令只取前 3 列**。`vel_command_b` 是 4 列（第 4 列是 heading 目标），`heading_command=False` 时它无意义；观测函数 `observations.velocity_command` 切前 3 列，否则拼接后是 57 维。

### 6.2 动作（16 维）

| 动作 | 维度 | 控制方式 |
| --- | --- | --- |
| FL/FR/RL/RR 腿部关节 | 4 × 3 | 位置目标 `q* = q_default + 0.25·a` |
| 四个车轮 | 4 | 速度目标 `ω* = 8.0·a` |
| **总计** | **16** | 连续动作 |

轮速上限 = `8.0 × 0.09 m = 0.72 m/s`，覆盖满幅前进指令 0.5 m/s 的 69%，留出跟踪误差和打滑余量。**指令范围和轮动作 scale 必须一起改**：只把 `lin_vel_x` 调到 1.0 而 scale 还是 8.0，策略会一直顶着 0.72 m/s 的饱和点白丢奖励。

腿部仍用 PD：`τ = K_p(q_des − q) − K_d q̇`。**车轮控制保持现有实现（速度目标接口）**，不与腿部一起改——同时动动作空间和控制接口，出问题无法归因。

### 6.3 奖励（10 项每步 + 摔倒 −10）

σ 是误差尺度。跟踪项用**有界柯西核** `1/(1 + e²/σ²)`（不是 `exp`：exp 在远端已经压到 0.018，梯度没了；柯西核在满幅误差处还剩 0.2），高度与姿态项都是**平方惩罚**，因为平地上机身本来就该平、高度本来就是设定值，需要的是零附近的刚度，而不是一个带天花板的奖金。惩罚项函数返回正值，符号由权重携带。

| # | 奖励项 | 函数 | 权重 |
| --- | --- | --- | --- |
| 1 | 前后、左右速度跟踪 | `1/(1 + [(vx−vx*)²+(vy−vy*)²]/0.25²)` | **+2.0** |
| 2 | 偏航角速度跟踪 | `1/(1 + (ωz−ωz*)²/0.3²)` | **+1.0** |
| 3 | 机身高度 | `((h−0.50)/0.05)²` | **−0.5** |
| 4 | Roll、Pitch | `(gx²+gy²)/0.2²` | **−0.5** |
| 5 | 垂直速度（上下弹跳） | `(v_z/0.2)²` | **−0.2** |
| 6 | 机身横滚/俯仰角速度 | `(ωx²+ωy²)/1²` | **−0.2** |
| 7 | 轮子空转（**严格零指令时**） | `1[cmd=0]·mean₄((q̇_w/2)²)` | **−0.2** |
| 8 | 关节默认姿态（只腿） | `mean_legs((q−q_default)/1.0)²` | **−1.0** |
| 9 | 腿部关节加速度 | `Σ_legs(q̈/2000)²` | **−0.02** |
| 10 | 动作变化率 | `Σ((aₜ − aₜ₋₁)/1.0)²` | **−0.01** |
| — | 摔倒终止 | `1[高度<0.33 或 倾角>0.5]` | **−10** |

```text
r = 2·r_v + 1·r_ω
    − 0.5·p_h − 0.5·p_ori − 0.2·p_vz − 0.2·p_ang
    − 0.2·p_wheel − 1.0·p_pose − 0.02·p_qacc − 0.01·p_action
    − 10·1[fallen]          ← 由 env 加，不是表里的一项
```

> 每步奖励都乘 `dt = 0.02`，所以正项上限是 `(2.0 + 1.0) × 0.02 = 0.06`/步。**读 `[terms]` 行时别忘这一步**：`track_lin_vel_xy=+0.029` 已经是满值的 72%（原始值 1.45/2.0）。

**没有存活加成（`alive`），也没有每步 0 下限。** 这两样都试过，都是为别的错误打补丁，现在一起删掉了。先有下限（legged_gym 的 `only_positive_rewards`：把每步奖励 clip 到 0），理由是"正项跟不住指令时会缩、罚项不会缩，于是早摔反而划算"；然后发现策略早期每步本来就是负的，下限把它统一压成常数 0，`Train/mean_reward` 整轮恒为 0、梯度全消失，于是又加 `alive +1.5` 把普通步抬到下限之上。

真正的根因是**奖励形状**（罚项在"不努力"时不缩）加上**归一化尺度把探索噪声计价成 −30/步**（见下面 9、10 项那一段），两处都已修，下限与加成随之失去理由。PPO 也不需要非负奖励：优势是 `A = R − V`，归一化只缩放不改序，**比 critic 预期稍微好一点的一步仍然得到正优势**。存活加成唯一确定的作用是给每步加一个常数偏移，把回报量级抬高，却不告诉策略怎么活。

**没有位置保持（`p_hold`）。** 位置保持（被推之后回到原处）是第四种能力，前三种是"能运动、能急停、能稳住站立"。它先在验收里**单独量**（第 9 行的 `drift` 列，见 §6.8），量出问题再给奖励项。把四个目标塞进同一个奖励，任何一个失败都无法归因——这正是奖励表此前越加越多的原因。

于是**"零指令＝不许动"由第 1 项自己承担**：指令为零时它就是"跟踪零速度"。剩下的唯一盲区是**腿把底盘撑住、轮子在空转**——机身完全静止，所有机体系通道都满意——这才是第 7 项存在的理由，也是全部 10 项里**唯一带门控**的一项。

**为什么是 10 项，而不是 16 项。** 上一版对每个轴组都配了一对通道：线速度一个 exp 核**加**一个二次项，偏航再来一对；另有带门控的位移项、以及三个量级小到测不出来的正则（腿关节速度只占 1%，关节力矩更小）。**同一个误差上有两个不同刚度的弹簧**，既无法归因也无法调参。收敛的做法是**替换而非追加**：

- 每个轴组只留一个核（第 1、2 项），柯西核在整个指令范围内都有梯度；
- 高度从 exp 奖金改成平方误差：平地上 0.50 m 是设定值，要的是刚度，不是天花板；
- 第 5 项补上"上下弹跳"：没有足端接触传感器时，颠着走是最廉价的"看起来在走路"，而第 3、4 项都看不见它；
- 第 9 项（腿关节加速度）替代腿关节速度项，第 10 项按 1.0 归一。这两项是让"抖"花钱的通道（见下）；
- 第 6 项和第 4 项不重复：第 4 项管**姿态**，第 6 项管**姿态角速度**——幅度很小但抖得很快的摆动，平均倾角接近 0，第 4 项几乎收不到钱；
- 删掉的 `wheel_slip`、`joint_torques` 都在别处已有等价约束：轮速被第 7 项管，力矩被第 9、10 项管。

**为什么第 9、10 项的归一化尺度是 2000 和 1.0（这一段是踩过的坑）。** 曾经为了"可读"，把动作变化率按 0.05 归一、腿加速度按 200 归一：这样"0.05 的动作跳变记 1 个单位"看起来漂亮。但归一化同时把**探索噪声**放大了同样的倍数——动作每步从 `N(0, σ)` 重采样，`σ = 0.5` 时步间差的标准差就是 0.7，于是 `Σ((Δa/0.05)²) ≈ 3200`，在权重 −0.01 下是 **−32/步**；腿加速度同理，噪声让 `q̈ ≈ 1700 rad/s²`，`12·(1700/200)²·0.02 ≈ −12/步`。两项合计 −44/步，而正项上限只有 4.5——**噪声项压过了整个正项面**，策略看见的奖励几乎全是噪声，`--iterations` 加多少都一样。改回 1.0 和 2000 之后同样的噪声只花 `8×0.01 = 0.08` 和 `12×0.72×0.02 = 0.17`。

代价要如实说：二次型惩罚分不清"噪声"和"嗡鸣"（二者都只是 `q̈`），所以能容忍噪声的权重对嗡鸣也只是轻拍——400 rad/s² 只花 0.01/步。抖动在一期主要由它丢掉的跟踪分来计价；等策略动作足够平滑、噪声地板降下来之后，再把权重加回去。

**为什么摔倒惩罚只罚真摔倒、而且由 env 加。** 第一版用的是 `mdp.is_terminated`——它**把 20 s 超时也算成终止**。于是"站满 20 s"和"第 40 步倒地"付同样的钱，剩下的差别只有倒地后少付的那些每步正则项：**早摔反而更划算**。现在这条惩罚**不是奖励表里的一项**，由 `isaaclab_m20/envs.py` 的 `M20VelocityEnv.step` 在 `terminated & ~truncated` 的步上直接加到交给学习器的张量里，量在 `M20WheeledVelocityEnvCfg.fall_penalty = -10`。

为什么不用奖励项：奖励项只能从机器人状态**重新推导**"是不是摔了"，于是高度/倾角判据存在两份，改一忘一就悄悄跑偏；而且 `TerminationManager` 在 `RewardManager` **之后**才计算，奖励项读到的只能是**上一步**的终止标志——落地那一步反而读不到（回合已重置）。用 `step` 里的标志则是"结束回合的那一对标志"，既不会重复收钱，也不会漏收。

**正常超时的惩罚恒为 0**：不罚、也不额外奖励——活满 20 s 本身就是被训练的能力，靠的是每步的正项，而不是一笔记账。这解释了一个现象：**tensorboard 里 episode length 一直很长，但一放出来机器人是倒的**——因为倒下的姿态既没过高度线也没过倾角线（曾经的 0.28 m / 0.8 rad 太宽），回合照样跑到超时。现在 0.33 m / 0.5 rad 会真正结束它。

**权重从 −200 降到 −10 是为什么。** 摔倒的**真实代价**是"丢掉本回合约 1000 步 × 每步几点的正奖励"，而不是那一次扣分；再叠一个 −200 只会把 value 的量级拉大、让 critic 更难学。−10 足够让"故意倒下"比"活得难看"更差，同时把回报留在可估的范围内。

**第 7 项为什么必须门控、且从命令缓冲读。** 不门控就会给原地转向收税（差速滚轮是转向的机制）；读 `is_standing_env` 则会踩到静默失败——标志没被置位时整条通道失效，日志里只看到它恒为 0，而机器人照样原地空转。所以判据是"命令缓冲严格为零"（`eps = 1e-3`），`scale = 2 rad/s ≈ 0.18 m/s`。

**为什么第 8 项只对腿、为什么用"均值 / 1 rad / −1.0"。** 腿的姿态项防止策略用奇怪折叠姿态维持平衡；轮子不能进——轮关节绝对角无界。注意它拉的是 `default_joint_pos`：如果标称站姿本身带俯仰（同侧前后腿 hip 偏置不等），这一项会把俯仰**强化**而不是纠正，机身水平靠第 4 项。`kp=80` 撑 34.5 kg（每腿 84.6 N、膝到轮心水平臂 0.143 m）的静态膝力矩约 12 N·m，静态下沉只有 ~0.15 rad，所以这一项最多吃掉 ~0.002/步——它是"别折叠"的保险，不是"跪下去"的税。

这一项的第一版是 `Σ_legs((q−q_default)/0.3)²`、权重 −0.05，设计点写的是"12 关节各偏 0.1 rad"。实测 `[terms]` 给出 `joint_deviation=-0.367`/步，反推原始值 **367**：12 关节平均偏离 1.65 rad，比设计点大 16 倍。而正项上限只有 0.06/步，于是"把腿收回来"这一项比策略能挣到的全部奖励还大 9 倍，PPO 看到的梯度几乎只有这一条，跟踪通道根本没机会说话（这也是 `neg=1.00`、`rew=-0.36` 的来源）。改法是**换形状而不是换权重**：取均值（12 个关节不该因为腿多就罚得多）、尺度放到 1 rad（0.3 rad 的二次在 1.6 rad 处是 28 倍惩罚，悬崖太陡）、权重 −1.0。现在同样 1.65 rad 折叠只值 −0.054/步，和 +0.06 的正项同一量级——这才是"一个 shaping 项"该有的比例。

**如果 `joint_deviation` 还是远超正项，先别调权重，先跑 `python -m isaaclab_m20.scripts.check_joints --headless`**：它会打印关节顺序、正则实际解析到的 joint_ids、`init_state.joint_pos` 与 USD `default_joint_pos` 是否一致，以及零动作 200 步后腿落在哪。"腿真的折了"和"配置里默认姿态对不上"是两种完全不同的故障，权重救不了后者。

**没有任何死区。** 零指令就是零运动，0.1 m/s 的"允许蠕动"不成立：一轮 20 s 能走 2 m，而验收里第 9 行量的是位移。

两条**刻意不做**的事：

- **不做与指令无关的绝对速度惩罚**。前进和后退本来就要求轮子和机身动，绝对量的惩罚是在给"按要求运动"收税。第 1、2 项减了指令，第 7 项只在零指令生效。
- **不强制四个轮子始终接触地面**，也不惩罚横向滑移（车轮不是全向轮，侧移时的横向刮擦就是产生侧移的机制，罚它等于禁止侧移）。

**为什么没有每步 0 下限（`only_positive_rewards`）。** 这道下限曾经在 `isaaclab_m20/envs.py` 里：把每步奖励 clip 到 0、摔倒的 −10 照付。算术动机是"正项跟不住指令时会缩、罚项不缩，活 1 秒净亏，于是早摔划算"。它确实能压住自杀策略，但代价是**只在普通步为正时成立**：策略早期每步是负的，下限把整段信号压成常数 0，`Train/mean_reward` 恒为 0、梯度只剩摔倒那一步——这正是"跑了一整轮，平均奖励全是 0"的原因。当时的补丁是加 `alive +1.5` 把普通步抬到下限之上。

现在下限和加成一起删掉了，因为它们治的是症状：真正的病因是奖励形状（罚项不随"放弃"而缩）和归一化尺度把噪声计价成 −30/步（见第 9、10 项那一段），两者都已修。删掉之后 `Train/mean_reward` 与 `Episode_Reward/*` 终于是同一套数字，可以直接读：**每步为负不是错误，是"这一步比预期差"**，PPO 用 `A = R − V` 照样能学；只要 `Train/mean_reward` 在爬，策略就在变好。

摔倒惩罚之所以还留在 −10 而不是跟着消失：它是**唯一一次性、且与死亡绑定的负事件**，没有它"倒下"和"站到超时"的回报差别只剩每步项的累计，而策略很容易发现早死能少付这些项。

### 6.4 指令（混合采样）

`MixedVelocityCommand`（`tasks/commands.py`），机体系 `(vx, vy, ωz)`，`heading_command=False`（直接给角速度，不让环境反算 heading；观测/奖励/部署三处口径一致）。

**每 2–4 s 重采样一次**。重采样不是三个轴独立均匀抽，而是按类型混合：

| 指令类型 | 采样比例 |
| --- | --- |
| 单方向运动 | 50% |
| 两个方向组合 | 30% |
| 三个方向组合 | 10% |
| 零速度指令 | 10% |

实现要点：**可用轴由 range 宽度决定**——某个轴的 `(min, max)` 退化成 `(0, 0)` 时它不参与采样，权重按 `[0.5, 0.3, 0.1][:可用轴数]` 重新归一化。所以阶段 2（只有 `vx`）自动退化成"50/30/10 全落在 `vx` 上 + 10% 零指令"，阶段 1（三个轴全零）则 100% 是零指令，不需要为每个阶段写一套采样逻辑。

零指令的 10% 是采样器默认值，**课程里每个阶段都会把它改掉**：阶段 1 = 100%、阶段 2 = 50%、阶段 3 = 30%、阶段 4 = 20%（`Stage` 的 `zero_prob` 字段，由 `CommandSchedule.apply_sampling()` 写回 `term.cfg`）。"每个阶段都留一份停止指令"是课程的骨架，不只是最后阶段的技巧：如果只在最后阶段补，前几个阶段会把"停住"从 actor 里训掉，之后再学就是灾难性遗忘——这正是"一 hold 住就溜、一停就倒"的来源。复习比例逐阶段下降，重心从站立平滑移到跟踪。`MixedVelocityCommand` 每次重采样都现读 `zero_prob`，所以下一拍就生效。

**阶段 4 再把保持时间改短**：`zero_prob` 0.20，保持时间 2–4 s → 1.5–3 s（`Stage` 的 `resampling` 字段，同样由 `CommandSchedule.apply_sampling()` 写回 `term.cfg`）。目的不是换范围，而是换**切换频率**：同一个策略必须在一回合里数次起步、停下、换向，两个门控的静态项也才有足够样本去压住残余速度。

| Actor / Critic Hidden | [256, 256] | 两层 MLP |
| Activation | ELU | 统一 |

| 采样参数 | 值 |
| --- | --- |
| `num_envs` | 4096（默认值，一般不用改） |
| `num_steps_per_env` | 24 |
| `episode_length_s` | 20 |
| `policy_dt` / `physics_dt` / `decimation` | 0.02 s / 0.005 s / 4 |
| `save_interval` | 50 |
| `max_iterations` | 3250（4 阶段合计） |

样本量：`4096 × 24 = 98,304` 条/轮；3250 轮 ≈ 3.2 亿条环境转移。注意 RSL-RL 每轮还对这批 rollout 做 5 遍 × 8 个 minibatch 的更新，所以不能把 3.2 亿理解成"网络只训练了 3.2 亿次"。

**关于 `schedule` 从 `adaptive` 改成 `fixed`（2026-11 的 `m20_v5` 之后）。** RSL-RL 的优化器是 Adam，Actor 和 Critic 各一个参数组。自适应调度每轮按实测 KL 把 lr 乘或除 1.5，并直接写进 `optimizer.param_groups[*]["lr"]`。问题是 Adam 的更新步长 `η·m̂/(√v̂+ε)` 里 `m̂/√v̂` 是尺度归一化的、近似 O(1)，**所以实际步长几乎正比于 η**；调度器一换 η，`v̂` 还停在旧尺度上，下一轮就是同样倍数的步长跳变。`max_grad_norm=1.0` 只防单次梯度爆炸，防不了"梯度正常、lr 被放大"。

`m20_v5` 的阶段 1 把这件事演示了一遍：`Loss/learning_rate` 在 0 和 2e-3 之间来回锯（一半迭代在 lr≈0 上空转），`mean_episode_length` 在第 40 轮就满 1000 并稳到第 200 轮，然后在 lr 尖峰处掉到 380、`Loss/value_function` 冒出 0.24 的尖峰。`Loss/entropy` 反而是单调下降的（11.5 → 4.27，即 σ 0.5 → 0.32），说明不是探索噪声把机器人撞倒的。固定 lr 之后步长尺度不再变，这才是 Adam 被设计出来时假设的工作条件；`desired_kl` 字段留着但不再生效。

对应地，阶段 1 的合理轮数是 **180–200**，不是 300：平台期在 40–200 之间，之后继续跑只是让它去撞不稳定的边界。

**关于 `Init Action Std` 从 0.9 改成 0.5。** 采样器给 16 个动作维度**同一个** σ，但这 16 维不是同一个量纲：一单位腿动作是 0.25 rad，一单位轮动作是 8 rad/s（0.72 m/s）。σ=0.9 意味着静止阶段的每一步都在给轮子下 ±7.2 rad/s（±0.65 m/s）的指令，比静止项想守的 0.15 m/s 大四倍——探索噪声本身就把"站住"变成了"乱走"。0.5 保留 ±7° 的腿抖动和 ±0.36 m/s 的轮噪声，随训练 RSL-RL 会自己收窄。

环境数量按显存选（Isaac Sim 本身要吃掉一部分）。**两个任务默认都是 4096，24 GB 的 4090 直接跑，不用传参数**：

| 显存 | 建议环境数 |
| --- | --- |
| 16 GB | 2048 |
| 24 GB | **4096（默认）** |
| 48 GB | 4096–8192 |
| 80 GB | 8192+ |

训练期间**只跑一个 Isaac Lab 训练进程**：PhysX GPU 缓冲、显存余量和 PPO 更新峰值是互相挤的，两个进程同时抢卡的表现是帧率崩到个位数，而不是 OOM——很难定位。

### 6.6 课程（4 阶段，阶段间续训）

`scripts/train.py` 的 `STAGES`。**每个阶段都从上一阶段的最佳模型继续训练，不重新初始化**。顺序是"先站稳 → 前后 → 全向（横移+偏航一起）→ 更快、含起步急停"，每个阶段都保留一部分零指令，让"站住"在学新动作时被反复复习：

| 阶段 | 名称 | 轮数 | 起始 → 结束指令范围 | warmup | 指令分布 |
| --- | --- | --- | --- | --- | --- |
| 1 | `1_stand` | 300 | `vx=0`，`vy=0`，`ωz=0`（零指令） | 0 | 零指令 100% |
| 2 | `2_forward_backward` | 700 | `vx: 0 → ±0.4`，`vy=0`，`ωz=0` | 150 | 零指令 50% |
| 3 | `3_multi_direction` | 1000 | `vx: ±0.4 → ±0.5`，`vy: 0 → ±0.2`，`ωz: 0 → ±0.6` | 300 | 零指令 30% |
| 4 | `4_agile` | 1250 | `vx ±0.5`，`vy ±0.2`，`ωz: ±0.6 → ±0.8` | 0 | **零指令 20%**，保持 **1.5–3 s** |

合计 3250 轮（`max_iterations` 口径，不是 PPO 的 `num_learning_epochs`）。

**为什么每个阶段都留零指令。** 这是这份课程最关键的一处修正。早先的版本只在最后阶段练停止，结果阶段 2 之后"站住"这项技能被持续地训掉：`eval` 里一 hold 住就往前溜，或者干脆一停就倒。零指令占比 100% → 50% → 30% → 20% 是一个**复习比例**：越往后越偏重跟踪，但永远不把停止从分布里拿掉。占比由每个阶段的 `zero_prob` 覆盖（见 §6.4），阶段 4 还把保持时间缩到 1.5–3 s，让一个 20 s 回合里有好几次起步/停下/换向。

**阶段 1 是零指令阶段**，它的作用是把后面所有阶段的基线定下来：站住高度、机身水平、轮子不空转、车身不漂移。零指令下跟踪项的含义就是"别动"，所以它不需要额外的奖励项。单独成一阶段（而不是塞进阶段 2 的 warmup）的理由是它能出一个自己的 checkpoint——如果阶段 2 之后的跟踪分还不如阶段 1 的"站着"，问题在指令和动作尺度上，不在基线。

**旧站立模型的 57 维观测搬不过来**（见下文），所以这条课程必须自己重新建立站立基线，这一步就是阶段 1；阶段间继承的是 Actor 和 Critic 的**全部参数**（同一个 runner 加载 checkpoint），不是只继承 Actor。

**warmup 是阶段内的线性 lerp**：每个阶段的指令范围都从"上一阶段的范围"出发，用前 `warmup` 轮线性长到本阶段的目标范围，之后固定。理由有两条：

1. 阶段 2 是第一次给非零指令，`vx` 直接给 ±0.4 会让策略一开局就满幅乱冲。从 `0` 起步，前 150 轮只是在阶段 1 的基线之上慢慢长出指令。
2. 阶段 3 刚换 checkpoint 时策略对新维度（`vy`、`ωz`）完全没概念，瞬间换满幅等于把上一阶段的能力打断。lerp 让新维度从 0 长出来，旧维度不受冲击。阶段 4 只把 `ωz` 从 0.6 放宽到 0.8 并把分布换成 20% 零指令，跨度小，不再需要 warmup。

**阶段 4 不改奖励，只改分布和保持时间。** 前三个阶段训练的是"给一个指令、保持 2–4 s、跟住它"，而实际使用中机器人要频繁起步和停下。阶段 4 保留 20% 零指令（比阶段 3 的 30% 略低），把每条指令的保持时间缩短到 1.5–3 s：一个 20 s 回合里有五到八次指令切换，而不是两三次长保持。它考验的正是 §6.3 里那两项门控项——同一个策略必须在一回合内既能在零指令下"卡住"不动，又能在非零指令下放开。warmup 给 0，因为范围与阶段 3 几乎相同（只有 `ωz` 从 0.6 放宽到 0.8），没有新维度要长出来；`zero_prob` 与 `resampling_time_range` 在 `CommandSchedule.apply_sampling()` 里写回 `term.cfg`，`MixedVelocityCommand` 每次重采样都现读这两个值，所以下一拍就生效，不需要重建 term。

如果阶段 4 的测试显示"起步慢、超调大、停下时还往前滑"，先加长这一阶段（`--stage 4 --iterations 1500`），而不是回到阶段 3 调奖励权重——这是分布问题，不是能力问题。

**旧站立模型怎么用**：它的观测是 57 维，速度指令任务是 56 维，**不能 `runner.load` 续训**。做法是把它的能力当作阶段 1（零指令站稳）要重新达到的目标——那个阶段本身就是"站稳 + 轮子不转"，策略会在几百轮内重新学到；不需要、也没法把权重搬过来。若要搬运，只能在 `assets`/`observations` 层面把两边对齐成同一维度，那是另一件事，第一版不做。

**阶段间续训流程**（`main()` 里）：

```text
for stage in stages:
    runner = OnPolicyRunner(env, agent_cfg, log_dir=<run>/stage{N}_{name})
    ckpt = 上一阶段目录里最新的 model_*.pt   # 单阶段运行时是 STAGES 里前一阶段目录
    if ckpt: runner.load(ckpt)
    schedule.start_stage(stage)              # 设指令范围到 ranges_from
    runner.learn(stage.iterations, init_at_random_ep_len=True)
```

**只建一个 env，跨阶段复用**：`gym.make` 一次，各阶段重新 `OnPolicyRunner` 但共享场景。重建 env 会重新抽 startup 随机化、重置 PhysX 缓冲，既慢又让阶段间对比失去可比性。

`--stage N` 单独跑某一阶段时会自动去前一阶段目录找 checkpoint，找不到就打 `[WARN]` 从头开始——不会静默地用一个错维度的权重。不给 `--run_name` 时它会自动沿用 `<experiment>/` 下最新的 run 目录（否则每次 `--stage N` 都会新建一个空目录、每次都找不到上一阶段）。

**同一阶段重训＝覆盖**。不给 `--run_name` / `--new_run` 时，脚本沿用最新 run，并在开训前把该阶段目录清空（旧的 `model_<更高迭代号>.pt` 必须删掉，否则 `latest_checkpoint()` 会把上一次的 1200 轮当成这一次 700 轮的结果，还会把它交给阶段 N+1 当起点）。想保留上一次做对比就加 `--new_run`（另开一个时间戳 run 目录），想原地追加就加 `--keep_logs`（此时要自己确认目录里没有更高迭代号的旧文件）。

**跨阶段默认用上一阶段最新的模型**：`latest_checkpoint(<run>/stage{N-1}_*)` 按迭代号取最大，不作任何"是不是这次练的"判断，所以上面的清空是它可靠的前提。`--resume_from` 只覆盖第一个被选中阶段的起点。

**checkpoint 命名**：文件名里的数字＝这一刻**已完成的累计迭代数**。rsl_rl 原本按循环下标存盘，最后一次保存会比实际轮数少 1（`--iterations 300` 留下 `model_299.pt`），`train.py` 在每阶段结束后把它改名为 `model_300.pt`；只修正这一个 off-by-one，若最后一个文件是中途保存（数字对不上）则原样保留，不编造轮数。因为计数器跨阶段累计，阶段 4 结束时最后一个文件大约是 `model_3250.pt`，而不是 `model_1250.pt`——看"这个阶段跑了多少轮"请看同一目录里相邻文件的差值或阶段日志，不要直接读文件名的绝对值。

**每阶段的轮数是参数**：单阶段训练直接写 `--stage N --iterations 1200`（`--stage` 已经选定了一个阶段，再写 `--iters_stageN` 是同一件事，多余）；`--iters_stage1 … --iters_stage4` 只在 `--stage all` 时才用得着——那时四个阶段连着跑、每个阶段的预算不同。`--stage_scale` 是按比例整体缩放。优先级：`--iters_stageN` > `--iterations` > 默认值 × `--stage_scale`。warmup 始终被裁到不超过该阶段预算的一半，所以缩到几次迭代也不会把整段吃光。

**每阶段跑完，脚本会打印下一阶段的建议命令**（`play --checkpoint …` / `eval --checkpoint …` / `train --stage N+1`），这就是"跑完先进模拟器看，再决定是否训练下一步"的工作流。

**每阶段该跑多少轮，要按 §6.8 的验收指标决定，不是机械跑满。** 表里给的是上限。

### 6.7 域随机化：第一版关闭

`m20_velocity_env_cfg.set_domain_randomization(env_cfg, enabled)`，默认 `enabled=False`（`--dr off`）：

| 项 | 关闭（默认） | `--dr full` |
| --- | --- | --- |
| 摩擦 | 1.0 / 1.0 | 0.5–1.25 |
| 机身质量 | +0 kg | +(-2, +3) kg |
| 质心 | 0 | x/y ±0.03，z ±0.02 |
| 推力 | 无（interval 1e9） | 每 4–8 s ±0.5 m/s |

**必须在 `gym.make` 之前调用**：`startup` 事件在建场景时被深拷贝进 manager，之后再改 cfg 不生效。

顺序是刻意的：**先固定地形和动力学参数，把速度跟踪训好，再加入摩擦、质量、地形随机化**。第一版就开满 DR，速度跟踪和鲁棒性会互相干扰，出问题时无法归因是"策略不会走"还是"扰动太大"。重置时的小扰动（姿态、关节、轮角）仍然保留——它是每个回合必须做的，不算随机化。

### 6.8 验收（`scripts/eval.py`）

**不要只看平均 Episode Reward**。用固定指令序列测，且**不在训练环境里评价**（eval 脚本强制关掉 DR、关掉指令重采样）：

```bash
python -m isaaclab_m20.scripts.eval \
    --checkpoint logs/rsl_rl/m20_velocity/<run>/stage4_agile/model_3250.pt
```

（文件名是累计迭代数，阶段 4 结束时约 3250 而不是 1250；也可以只传目录或 `--stage 4` 让脚本取最新。）

| 测试 | 指令 `(vx, vy, ωz)` | 运动 |
| --- | --- | --- |
| 1 | `(0.30, 0, 0)` | 前进 |
| 2 | `(-0.30, 0, 0)` | 后退 |
| 3 | `(0, 0.20, 0)` | 左移 |
| 4 | `(0, -0.20, 0)` | 右移 |
| 5 | `(0, 0, 0.50)` | 左转 |
| 6 | `(0, 0, -0.50)` | 右转 |
| 7 | `(0.30, 0, 0.30)` | 前进并左转 |
| 8 | `(-0.30, 0.20, -0.30)` | 后退、左移并右转 |
| 9 | `(0, 0, 0)` | 保持静止 |
| 10 | `(0.30,0,0)` ↔ `(0,0,0)` 交替 3 轮 | 起步 / 停下切换（对应课程阶段 4） |

| 指标 | 验收标准 |
| --- | --- |
| 前进 / 后退速度 RMSE | < 0.10 m/s |
| 左右速度 RMSE | < 0.12 m/s |
| 偏航速度 RMSE | < 0.15 rad/s |
| Roll RMS | < 5° |
| Pitch RMS | < 5° |
| 平地摔倒率 | < 2%（= 20 次/1000 策略步） |
| 零指令时机身速度 | < 0.05 m/s，`|ωz|` < 0.10 rad/s |
| 零指令时净位移（8 s 窗口内相对起点的平均距离） | < 0.25 m |
| 切换测试：加速段速度误差 / 停稳后残余速度 | < 0.12 m/s / < 0.08 m/s |

切换测试每段指令 2 s，每段的前 1 s 当瞬态丢掉、只统计后 1 s，所以量的是"停稳之后还在不在往前滑"而不是"刹车要多久"。阶段 4 用 20% 零指令 + 1.5–3 s 保持专门练过这一项，所以这一行的分数主要看那一阶段。

第 9 行现在还多一列 `drift`：**零指令能力是"位移"主张，不只是"速度"主张**——0.05 m/s 的蠕动能过速度阈值，却在 8 s 里走 0.4 m。这一列刻意只做诊断，不参与 PASS/FAIL 之外的奖励：奖励里目前没有位置保持项（见 §6.3），所以它退化时该做的是先看 `[health]` 的 `|v_xy|` 与 `standing=`，判断是策略在漂、还是指令缓冲没归零。

这些是**工程验收目标，不是 PPO 必然能达到的结果**。单项不过关时按下面顺序查：

1. 摔倒率超标 → 先看是不是 Stage 3 的 `ωz ±0.6` 配 `vy ±0.2` 太激进，回到 Stage 2 的验收再前进；Stage 4 的 `ωz ±0.8` 应该只在阶段 3 通过之后再上。
2. 速度 RMSE 大但方向对 → 轮动作 scale 是否够（`8.0 × 0.09 = 0.72 m/s`）；若策略明显不敢动，看 `[health]` 的 `standing=`：行驶时应为 0.00，若一直 1.00 说明指令没进缓冲。（唯一的门控项是 `wheel_speed`，它只影响零指令时的奖励，不会压住前进。）
3. 侧移差 → 检查 `track_lin_vel_xy` 的 σ=0.25 对 0.2 m/s 的小指令是否太大（σ 不随指令收缩，小指令下梯度偏平，必要时给小指令单独一套 σ，或把 σ 降到 0.15）。
4. 零指令漂移 → **零指令就必须零运动**。判据用 `eval` 第 9 行（零指令）的 `mean_speed`、`drift` 与 `[health]` 的 `|v_xy|`：速度 > 0.05 m/s 或净位移 > 0.25 m 就要处理。先确认这一项确实是 0（`[health]` 的 `standing=` 是否为 1.00），再看 `wheel_speed` 的量级——它若很大而位移为 0，是"腿撑住底盘、轮子空转"；两者都小却仍漂，说明跟踪核在低误差处的梯度不够（柯西核 σ 从 0.25 收到 0.2），而不是缺项。
5. 起步/停下迟钝（阶段 4 特有） → 加长这一阶段（`--stage 4 --iterations 1500`），不要动跟踪权重。停下后仍前滑：先把 `track_lin_vel_xy` 的 σ 收紧（0.25 → 0.2），让"零速度"在零附近更陡；还不收敛再考虑加回一个门控位移项（§6.3 里被删掉的 `p_hold`），但那属于第四种能力，应单独验证。**抖动**则看 `leg_joint_acc` 与 `action_rate`，以及 `ang_vel_xy`。

### 6.10 看这些指标

| 指标 | 期望趋势 |
| --- | --- |
| `Episode_Reward/track_lin_vel_xy` | 往 2.0 爬。**长期 < 0.5 就是速度跟踪没学会** |
| `Episode_Reward/track_ang_vel_z` | 往 1.0 爬（阶段 3 之后才有意义，前 2 阶段 ωz 指令恒为 0） |
| `Episode_Reward/flat_orientation` | 负值，往 0 爬（现在是平方惩罚，越平越接近 0；阶段 1 就该接近 0） |
| `Episode_Reward/ang_vel_xy` | 负值，小幅（0.05 量级）。**和 `flat_orientation` 分开读**：姿态平但这一项大 = 机身在小幅快抖 |
| `Episode_Reward/base_height` | 负值，往 0 爬（平方误差 /0.05，5 cm 偏差记 1.0）。**它和阶段 1 的"站了起来"直接对应** |
| `Episode_Reward/wheel_speed` | 负值，只在严格零指令时有量。**它很大而 `[health]` 的 `|v_xy|` 很小 = 腿把底盘撑住、轮子在空转**；它接近 0 说明轮子没在空转 |
| `Episode_Reward/joint_deviation` | 负值，**均值形式**（12 腿关节取平均、1 rad 归一整）。标称站姿的 `kp=80` 静沉 ~0.15 rad → 原始值 ~0.02 → 每步 ~−0.0005、整回合 ~−0.5；**它一旦比跟踪项还大（比如 `[terms]` 里 −0.3 以上）说明腿在折叠**，不是"再调权重"，而是先跑 `check_joints` 看腿到底去了哪 |
| `Episode_Reward/leg_joint_acc` | 小幅负值（`q̈/2000`：正常步态 ~0.02，探索噪声地板 ~0.17）。**明显高于 0.2 说明关节在嗡鸣**，先加这一项的权重（−0.02 → −0.05），不要动跟踪项 |
| `Episode_Reward/action_rate` | 小幅负值（按 1.0 归一：噪声地板 ~0.08）。抖动的第二道闸门，和 `leg_joint_acc` 一起读 |
| `Train/mean_reward` | 学习器真正优化的每回合回报（**没有** 0 下限，也没有存活加成）。它是每步项的累计，**可以是负的**，只要在爬就说明在变好；一直不爬且 `[health]` 的 `neg` 贴着 1.00，说明这一阶段的指令跑在策略能力前面 |
| `[health] fall_rew` / `timeout_rew` | 终端行里直接看的两项：摔倒步实际交给 rsl_rl 的奖励（应 ≈ −10）与超时步（应 ≥ 0）。**没有 `Episode_Reward/termination_penalty` 曲线了**——这条惩罚由 `M20VelocityEnv` 在奖励管理器之后加，只出现在 `Train/mean_reward` 与 `[health]` 里 |
| `Episode_Termination/base_height` / `bad_orientation` | 从高往低降，阶段 2 末应 < 10% |
| `Episode_Termination/time_out` | 应接近 1（绝大多数回合跑到 20 s）。**它和上面两项加起来不到 1，说明有回合被别的条件截断** |
| `Episode/length` | 就是"平均活了多少步"。满值 1000 步；**如果这一项很高但录像里机器人在趴着，先看 `base_height`/`bad_orientation` 是否真的在涨**——终止判据没触发时，倒地也会跑满 20 s |
| `Loss/learning_rate` | 自适应，学不动时自动降 |
| `[terms]` 行（默认每 200 步） | `--per_term_every` 打开，`[terms] per-step (value×weight×dt)` 逐项列出**每步实际进账**，末尾 `sum=` 应与同一时刻 `[health]` 的 `rew=` 相等（摔倒罚在之后才加，会差那一步的 −10）；下一行 `[terms] episode sums` 是 `_episode_sums` 的均值，也就是 tensorboard 的 `Episode_Reward/*`。**权重之间唯一可比的尺度是 per-step 那一行**——episode sums 会随回合变长而变大，一项权重严重过大时在那里也可能看不出 |

终端里每 50 轮打印 `[cmd] iter=... vx=... vy=... wz=...`（当前阶段与当前指令范围），退火期间能看到范围在长；每个阶段开始时还会打印一行 `[cmd] stage=... hold=...s zero_prob=...`，阶段 4 的 0.20/1.5–3 s 就在这一行里核对。`[health]` 行里的 `rew=` 是每步奖励的均值（**未做任何裁剪**，为负是正常的），`neg=` 是"负奖励步数占比"：`neg` 贴着 1.00 且 `Train/mean_reward` 不爬，说明这一阶段的指令已经跑在策略能力前面。**换阶段那一刻跟踪分会掉一下**（新维度从 0 长出来），看它能不能在 warmup 内爬回来；如果爬不回来，说明上一阶段的 checkpoint 没被正确加载（检查 `[INFO] Continuing from ...` 那行）。

**`[terms]` 行怎么用**：看到 `rew=-3.4` 时不要猜，直接看同一行的分解——比如 `joint_deviation=-1.9  action_rate=-1.2  leg_joint_acc=-0.4  track_lin_vel_xy=+0.3`，立刻知道负号来自哪两项。若某一项稳定压过整个正项面（正项上限 = 2.0 + 1.0 = 3.0），先调那一项的权重或尺度，而不是加存活加成或裁剪奖励（`[terms]` 的设计就是让这种"某一项把信号压平"的情况在终端里可见，而不是等一整轮 `Train/mean_reward` 恒 0 才发现）。

**训练总量参考**：`4096 × 24 × 3250 ≈ 3.2 亿` 条转移。4090 上 4096 环境的每轮耗时比 1024 环境高约 3–4 倍，但每轮见到的样本也多 4 倍；整条课程是数小时量级，具体看 tensorboard 的 `fps` 和每阶段的 `finished in ... min`。显存不够时降 `--num_envs`，别降 `num_steps_per_env`（24 步是 20 s 回合在上千环境下的抓取窗口）。
