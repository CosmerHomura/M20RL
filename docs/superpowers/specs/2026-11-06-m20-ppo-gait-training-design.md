# M20 轮足机器人 PPO 步态训练 — 设计文档

- 日期：2026-11-06
- 状态：已确认（待实现）
- 目标读者：项目作者（学习 PPO 算法 + 期望快速训出可用步态）

## 1. 背景与目标

M20 是一台 4 条腿 × 4 关节（hipx / hipy / knee / wheel）的轮足式四足机器人，总质量约 34.5 kg，MuJoCo 模型已就绪（`model/M20.xml` + `model/meshes/*.STL`）。

**本项目目标**：在 MuJoCo 中用成熟的 PPO 实现（stable-baselines3）训练一个「轮式驱动 + 速度指令追踪」策略。

**明确的目标边界**：

- ✅ 第一版做**轮式驱动**：轮子负责前进/横移，腿负责维持机身高度与姿态；不做腿部 trot、不做轮腿混合越障。
- ✅ 训练**速度指令追踪**：策略同时接收前向 `vx`、侧向 `vy`、偏航角速度 `ω` 三条指令并追踪。
- ✅ 使用 SB3 封装好的 PPO，重点放在观测/动作/奖励设计上，PPO 内部数学细节不手写。
- ❌ 不做：地形课程学习、sim2real、对抗扰动训练、多机器人。

**成功标准**：

1. 训练曲线 `ep_rew_mean` 稳定上升并收敛。
2. 速度追踪误差明显缩小（稳态 `|vx - vx_cmd| < 0.1 m/s`）。
3. 连续 > 10 s 不摔倒，并能响应指令变化（加速 / 横移 / 转向）。
4. `play.py` 渲染出的步态人工确认合理。

## 2. 技术选型

| 选项 | 结论 | 理由 |
|---|---|---|
| MuJoCo 3.x | 采用 | 已有模型、跨平台、CPU 上仿真速度快 |
| gymnasium | 采用 | SB3 的标准环境接口，替代已弃用的 `gym` |
| stable-baselines3 (PPO) | 采用 | 成熟稳定的 PPO 实现，自带 `VecEnv` / `VecNormalize` / 回调 / 日志 |
| rsl_rl / legged_gym | 不采用 | 绑定 IsaacGym/IsaacLab，需 Linux + NVIDIA GPU（≥8GB 显存）；本机 GTX 1650 Ti 4GB 无法承担 |
| CleanRL | 不采用（可作后续补充） | 单文件透明实现，适合之后对照阅读 PPO 内部细节，但不属于开箱即用 |

**计算设备决策（基于实测，不凭感觉）**：

MuJoCo 物理仿真运行在 CPU；SB3 PPO 的策略网络仅约 8 万参数，GPU 带来的计算加速远小于每步 CPU↔GPU 传输开销，典型结果是 GPU 更慢。因此：

- 默认 `device="cpu"`。
- `n_envs = 10`（本机 12 逻辑核，留 2 个给主进程与系统）。
- **M0 里程碑中做 60 秒 CPU vs GPU 基准实测**，若实测 GPU 更快则改 `device="cuda"`，以数据为准。

## 3. 项目结构

```
M20RL/
├── model/
│   ├── M20.xml              # 训练用模型（按 §4 做修正）
│   └── meshes/              # STL 网格（保持不变）
├── m20rl/
│   ├── __init__.py
│   ├── config.py            # 全部配置（dataclass）：环境、奖励权重、随机化范围、训练超参
│   └── env.py               # M20Env(gymnasium.Env)
├── scripts/
│   ├── train.py             # 多进程环境 + VecNormalize + PPO 训练入口
│   ├── play.py              # 加载模型 → 渲染 → 录视频
│   └── benchmark.py         # M0 用的 CPU vs GPU / 单环境 FPS 基准
├── logs/                    # TensorBoard 日志、模型 checkpoint、vecnormalize.pkl（gitignore）
├── requirements.txt
└── README.md
```

**设计原则**：

- `config.py` 是唯一调参入口（奖励权重、指令范围、超参都在这），`env.py` 只实现逻辑、不硬编码数值。
- `env.py` 单一职责：只负责 MuJoCo 步进、观测构造、奖励计算、终止判定；不掺训练逻辑。
- 训练脚本与回放脚本分离，二者共享 `config.py` 与 `env.py`。

**requirements.txt**：`mujoco>=3.0`、`gymnasium>=0.29`、`stable-baselines3>=2.3`、`torch`、`numpy`、`tensorboard`；可选 `imageio[ffmpeg]`（录视频）。

## 4. `M20.xml` 需要修正的内容

1. **轮子关节限位（需验证并显式声明）**：4 个 `*_wheel_joint` 未声明 `range`，文件头有 `<compiler autolimits="true"/>`。按 MuJoCo 语义，`autolimits=true` 时关节"是否有限位"由是否写了 `range` 推断，因此轮子**很可能已无限位**（此前的判断有误）。为避免依赖推断行为、跨 MuJoCo 版本保持确定，仍给 4 个 wheel joint 显式加 `limited="false"`，并用单元测试断言 `jnt_limited == 0`。
2. **初始高度**：XML 中 `base_link pos="0 0 1"` 会自由落体。不在 XML 中改，改在 `env.reset()` 中设置基座高度约 0.50 m（腿长约 0.5 m、轮半径 0.09 m）并叠加小随机。
3. **传感器**：XML 中的 accelerometer / gyro / framequat 保留不动，但 v1 训练不使用——观测直接从 `data.qpos` / `data.qvel` 计算，更快更清晰。

已确认无需修改：接触排除（各腿内部 body 互不碰撞）、16 个电机的 `ctrllimited` 与 `ctrlrange`（腿 76.4 N·m、轮 21.6 N·m）。

### 4.1 默认站姿

所有关节"归零"时腿是垂直伸直的（髋到膝 0.25 m、膝到轮 0.25 m）。要让基座停在 0.50 m（轮心离地 = 轮半径 0.09 m），两段腿需各弯折，竖直投影为 0.41 m：

- `hipx = 0`
- `hipy ≈ 0.61 rad`、`knee ≈ -1.22 rad`（大腿前摆、小腿后折，竖直投影 2 × 0.25 × cos(0.61) ≈ 0.41 m）
- `wheel = 0`

以上为 `config.py` 中的 `default_joint_pos`。**关节正负号以 M0 可视化校准确认**（MuJoCo 中轴为 `0 -1 0`，符号可能与直觉相反）；若校准后发现符号相反，只需改 `config.py` 中的默认角，不动逻辑。站立高度目标 `h_target = 0.50 m` 与本节一致。

## 5. 观测空间与动作空间

### 5.1 动作（16 维连续）

- 空间：`Box(low=-1.0, high=1.0, shape=(16,))`
- 顺序：`fl, fr, hl, hr × (hipx, hipy, knee, wheel)`
- 语义（2026-11-06 修订，原因见下）：
  - **腿部关节（hipx / hipy / knee）**：目标角偏移量的归一化值，`q_target = q_default + a × 0.4 rad`，环境内部用 PD 回路跟踪：`τ = 100·(q_target − q) − 5·dq`，再饱和到 ±76.4 N·m。
  - **轮关节**：直接力矩，`τ = a × 21.6 N·m`。
- PD 在物理步长（500 Hz）上计算，即每个控制步 10 次。若只在 50 Hz 更新一次，离散阻尼项对轻质小腿不稳定（实测会出现 ±40 rad/s 的振荡）。
- 归一化原因：PPO 的高斯策略对输出尺度敏感，统一到 [-1, 1] 让不同量程的关节被公平学习。

**为什么从"纯力矩"改为"PD 位置目标"**：M1 前的 100k 步试验中，纯力矩控制的回合长度只有约 15 步；给恒定重力补偿力矩，机器人 3 s 内高度从 0.50 m 掉到 0.10 m。原因是策略必须从零学一个闭环反馈律，而初始高斯探索的噪声约 ±76 N·m。改为 PD 后，`a = 0` 时机器人就能稳定站立（10 s 高度保持 0.47–0.50 m），探索退化为"在稳定姿态附近调整"，100k 步内回合长度即从 136 涨到 315 步。legged_gym / rsl_rl 等同类系统均采用此方案。

### 5.2 观测（60 维连续）

| 分量 | 维度 | 说明 |
|---|---|---|
| 基座线速度（机身系） | 3 | 追踪目标的核心依据 |
| 基座角速度（机身系） | 3 | 感知晃动机身与转向实际值 |
| 重力向量机身系投影 | 3 | 等价于 roll/pitch，判断是否倾斜 |
| 速度指令 `(vx, vy, ω)` | 3 | 任务输入；`ω` 即偏航角速度指令 |
| 关节位置 `q` | 16 | 相对默认站姿的偏移 |
| 关节速度 `dq` | 16 | |
| 上一拍动作 | 16 | 促使动作平滑 |
| **合计** | **60** | |

设计说明：

- 线速度、角速度均取**机身坐标系**，避免策略依赖绝对朝向，泛化更好。
- **不加入绝对航向角 yaw**：任务只追踪相对速度，绝对朝向与之无关，加入只会成为噪声。指令中的第 3 维是**角速度**而非航向角。

## 6. 奖励函数与终止条件

### 6.1 奖励（8 项加权和，每项连续可导）

| # | 项 | 公式 | 权重 |
|---|---|---|---|
| 1 | 前向速度追踪 | `exp(-4·(vx - vx_cmd)²)` | 1.5 |
| 2 | 侧向速度追踪 | `exp(-4·(vy - vy_cmd)²)` | 1.0 |
| 3 | 偏航角速度追踪 | `exp(-4·(ω - ω_cmd)²)` | 1.0 |
| 4 | 机身水平 | `-(gx² + gy²)` | 1.0 |
| 5 | 机身高度 | `exp(-20·(h - 0.5)²)` | 1.0 |
| 6 | 省力（力矩平方和） | `-Στ²` | 1e-5 |
| 7 | 动作平滑 | `-Σ(a_t - a_{t-1})²` | 0.01 |
| 8 | 零指令保持静止 | 当 `‖cmd‖ < 0.1` 时：`-(vx² + vy²)` | 1.0 |
| — | 存活奖励 | 每步 +0.2 | — |

所有权重集中在 `config.py` 的 `RewardConfig` 中，便于单独消融调试。

### 6.2 终止条件

| 条件 | 处理 |
|---|---|
| 基座高度 < 0.25 m（摔了） | 提前终止，本步大额负奖励 |
| 俯仰/横滚角绝对值 > 0.7 rad（侧翻） | 提前终止，大额负奖励 |
| `base_link` 的碰撞体触地 | 提前终止，大额负奖励 |
| 达到 500 步（10 s） | 正常 truncate，不罚 |

### 6.3 时间步

- MuJoCo 物理步长 `timestep = 0.002 s`
- 控制频率 50 Hz → 每个控制步 10 个物理子步（`dt = 0.02 s`）
- 每个 episode 最多 500 个控制步 = 10 s

## 7. 训练时的随机化（轻量 domain randomization）

| 项目 | 范围 |
|---|---|
| 速度指令重采样 | 每 4 s 一次；`vx ∈ [-0.6, 0.6]`、`vy ∈ [-0.3, 0.3]`、`ω ∈ [-0.6, 0.6]` rad/s；10% 概率给零指令 |
| 关节初始角 | 默认站姿 ± 0.1 rad |
| 基座初始高度 | 0.495 ~ 0.520 m（避免初始穿地或自由落体；站立时轮心离地 0.09 m，基座 0.50 m 即刚好触地） |
| 基座初始姿态 | roll/pitch ± 0.05 rad |
| 地面摩擦系数 | 0.7 ~ 1.2 |

先做以上轻量随机化；不加入质量/质心/延迟随机化（留待后续需要 sim2real 时再加）。

## 8. SB3 PPO 训练超参

| 参数 | 值 |
|---|---|
| `policy` | `MlpPolicy`，`net_arch=[256, 256]` |
| `n_envs` | 10（`SubprocVecEnv`，Windows 下必须 spawn 启动方式） |
| `device` | `"cpu"`（M0 基准实测后再定，见 §2） |
| `n_steps` | 2048 |
| `batch_size` | 512 |
| `n_epochs` | 5 |
| `gamma` / `gae_lambda` | 0.99 / 0.95 |
| `clip_range` | 0.2 |
| `learning_rate` | 3e-4 |
| `ent_coef` | 0.01（刻意调高，避免收敛到"站着不动"的局部最优） |
| `vf_coef` / `max_grad_norm` | 0.5 / 0.5 |
| `total_timesteps` | 先 5M 验证，再 20~30M 收敛 |

**速度调优（2026-11-06）**：PD 回路改为每 2 个物理子步更新（250 Hz），比每个子步更新快约 1.9 倍且同样稳定；`n_epochs` 10→5、`batch_size` 256→512、`torch.set_num_threads(2)`。端到端训练吞吐从约 1500 提升到约 2400 train-steps/s。`eval_freq` 从 50k 提到 100k，减少评估开销。

**VecNormalize**：`norm_obs=True`、`norm_reward=True`、`clip_obs=10.0`。训练结束保存 `vecnormalize.pkl`，`play.py` 必须复用同一份，否则观测分布不一致会导致策略失效。

**日志与保存**：TensorBoard 记录各奖励分项、episode 长度、追踪误差；每 200k 步保存一次 checkpoint；保留 `best_model`（按评估回合平均奖励选）。

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| 策略学到"站着不动"或"原地抖" | 提高 `ent_coef`；确保零指令只占 10% 且静止项权重不压倒追踪项；M1 先只追前向速度建立正反馈 |
| 仿真不稳定（腿穿透、弹飞） | 物理步长 0.002 s；必要时收紧碰撞几何或提高 `solref` 阻尼；降低力矩上限做课程 |
| 奖励 hacking（如用腿撑地蹭着走） | 动作平滑项 + 力矩惩罚；必要时加"机身不触地"的硬终止 |
| 轮子仍受限位（若修正遗漏） | M0 验收时显式检查 wheel joint 的 `limited` 属性 |
| 训练时间过长（CPU） | 10 个并行环境；M1 用 5M 步先验证；必要时降低 `n_steps` 或先训单指令 |
| Windows 多进程问题 | `SubprocVecEnv` 必须用 spawn（`if __name__ == "__main__"` 保护 + `multiprocessing.set_start_method("spawn")`） |

## 11. 不做的事（YAGNI）

- 不做 sim2real 部署与电机控制接口对接
- 不做地形课程学习、楼梯、越障
- 不做多算法对比（SAC/TD3），除非 PPO 明显失败
- 不做绝对航向角追踪
- 不做视觉/激光输入
