# M20 控制细节

这份文档只讲**控制**：谁在哪一层闭环、增益是多少、为什么是这些数、边界条件在哪。奖励设计与课程安排见 [algorithm.md](algorithm.md)，环境搭建见 [isaaclab_setup.md](isaaclab_setup.md)。

一句话概括分层：**策略 50 Hz 出 16 维目标 → 执行器 200 Hz 闭环跟踪 → 零指令时环境额外给四个轮子挂一个位置外环。**

---

## 1. 时间尺度与调用链

| 层 | 频率 | 周期 | 位置 |
| --- | --- | --- | --- |
| 物理仿真 | 200 Hz | 5 ms | `sim.dt = 0.005` |
| 执行器（PD / 速度伺服） | 200 Hz | 5 ms | PhysX 隐式执行器 |
| 策略 | 50 Hz | 20 ms | `decimation = 4`，`step_dt = 0.02` |

一个策略步里：`env.step(action)` → 轮子驻车环改写四个轮子列 → action manager 把 16 维 `[-1,1]` 映射成关节目标 → 4 个物理步 → reward / termination → 观测。

`[terms] per-step` 里的每一项都乘了 `step_dt = 0.02`，所以**策略每步**的奖励和 `Train/mean_reward` 是同一个尺度；不要拿它和"每毫秒"或"每物理步"的数混着看。

## 2. 动作接口

16 维连续动作 `a ∈ [-1, 1]^16`，全是**目标值**，不是力矩：

| 组 | 维度 | 映射 | 执行器类型 |
| --- | --- | --- | --- |
| 腿部 12 关节 | 12 | `q* = q_default + 0.25·a` | 位置 PD（`stiffness=80`） |
| 四轮 | 4 | `ω* = 27.78·a` rad/s | 速度伺服（`stiffness=0`） |

- 腿：`q_default` = `[hipx 0, hipy 0.61, knee −1.22] × 4`，`0.25 rad` 是单步能走的极限，也是"目标不可能离标称姿态太远"的保证。
- 轮：`27.78 rad/s × 0.09 m = 2.5 m/s`，这是**课程速度包线的来源**。电机本身允许 200 rad/s（18 m/s），所以包线是动作尺度定的，不是硬件定的。改 `scale` 等于改整套动作语义，旧 checkpoint 全部作废。
- 轮半径 0.09 m；轮转动惯量 `I_yy = 0.002853 kg·m²`（URDF/MJCF 一致，自转轴为 y）。

**策略看到的不是原始指令。** 观测第 37–39 维来自 `isaaclab_m20/tasks/control.py` 的
`command_target(env)`，内容是

```text
obs[37:38] = (vx*, vy*)  指令系速度经 R(−ψ_rel) 旋到机体系
obs[39]    = ω*          外环航向 PD 的输出（ROTATE 模式下就是 ωz*）
```

奖励里的速度/偏航跟踪也读同一份 `command_targets(env)`，所以"策略在追什么"和"奖励
在量什么"永远是一个定义。完整推导见 [algorithm.md](algorithm.md) §6.2.2；四轮驻车环
不受影响（它读的是原始指令的模式标签，见下面 §4）。

## 3. 执行器参数，以及由它们决定的数

`isaaclab_m20/assets/m20.py`：

| 组 | stiffness (kp) | damping (kd) | effort_limit_sim | velocity_limit_sim |
| --- | --- | --- | --- | --- |
| `legs`（12） | **80.0** | **2.0** | 76.4 N·m | 40 rad/s |
| `wheels`（4） | **0.0** | **2.0** | 21.6 N·m | 200 rad/s |

`τ = kp·(q* − q) + kd·(ω* − q̇)`，被 `effort_limit_sim` 截断。

由此得到的硬约束（这些数在调参时比"感觉"可靠）：

| 量 | 值 | 推导 |
| --- | --- | --- |
| 腿力矩饱和对应的位置误差 | `76.4 / 80 ≈ 0.95 rad` | 目标只有 ±0.25，所以只有**外力**能把腿顶到饱和 |
| 腿静态下沉 | `≈ 0.15 rad` | 每腿 84.6 N、膝到轮心水平臂 0.143 m → 12.1 N·m ÷ 80 |
| 轮速环时间常数 | `I/kd ≈ 1.4 ms` | 带宽 ≈ 700 rad/s |
| 轮力矩饱和对应的转速差 | `21.6 / 2 = 10.8 rad/s` | 2.5 m/s 的指令是 27.8 rad/s，所以打到饱和只需 39% 的指令转速 |
| 单轮法向力 | `≈ 84.6 N` | 34.5 kg ÷ 4 |
| 摩擦可用牵引力 | `≤ 84.6 N/轮`（μ=1.0） | 四轮 338 N，对应 9.8 m/s² 上限 |
| 电机可用牵引力 | `21.6/0.09 = 240 N/轮` | 四轮 960 N → **牵引受限，不是电机受限** |

## 4. 零指令时的轮子驻车环

### 4.1 为什么需要它

轮子是 `stiffness = 0` 的速度伺服，而 **PhysX 不建模滚动阻力**：静摩擦只阻止滑动，不阻止滚动。所以零指令下唯一抵抗滚动的是转速伺服的 `damping`，平衡在

```
q̇_eq = F_bias / (4 · kd)
```

`F_bias` 是机身倾斜带来的重力分量。34.5 kg 只要倾斜 **0.9°** 就有 5.3 N，代入 `kd = 2`：

```
q̇_eq = 5.3 × 0.09 / (4 × 2) = 0.06 rad/s ≈ 5.4 mm/s
```

8 s 就是 4 cm 位移，正好压在验收线（`eval` 第 9 行：0.05 m/s、0.25 m 净位移）附近。麻烦在于**策略没法把它压掉**：它的轮动作只能命令 `ω*`，而 `ω* = 0` 恰恰就是这条蠕变的解——策略再努力，也只是命令了一个"正好的零"，剩下的由物理自己流走。

### 4.2 控制律：级联，外环只有 P

零指令时把四个轮子动作列**替换**成位置外环的输出：

```
ω* = clip(kp_pos · (q_hold − q), ±ω_max)      # 新增：位置外环（P）
τ  = kd · (ω* − q̇)                             # 原有：速度内环（不动）
```

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `wheel_park_kp` | **15 s⁻¹** | 位置外环增益，时间常数 67 ms |
| `wheel_park_omega_max` | **3 rad/s**（0.27 m/s） | 外环输出的转速上限 |
| `wheel_park_error_clamp` | **0.3 rad**（2.7 cm 滚动） | 超过就重锚 |
| `wheel_park_enabled` | `True` | 总开关 |

### 4.3 "外环的 kd" 是多少？—— 没有，也不需要

这一点必须讲清楚，因为它容易被误读成"位置环的阻尼可以调"：

- **驻车环没有自己的 `kd`**。执行器始终是纯速度伺服，`kd` 是**全环境共享的 2.0**（腿和轮都是 2.0），驻车环只是把 `ω*` 从"策略给的值"换成"位置误差算出来的值"。换句话说，阻尼已经是 2.0，而且它本来就**低**——需要担心的从来不是"阻尼太高"，而是"刚度太高"。
- 让位置环稳定的阻尼，来自速度内环本身。两个环的带宽差：

```
速度内环  kd/I = 2.0 / 0.002853 ≈ 700 s⁻¹
位置外环  kp_pos = 15 s⁻¹
比值      47 : 1
```

  级联时内环比外环快 47 倍，外环看到的是一个"几乎瞬时"的速度跟踪，闭环呈现**过阻尼的一阶响应**（时间常数 67 ms），没有过冲、没有极限环。这也是为什么**不需要**给外环单独加阻尼项：加了会与内环的粘性重叠，反而让"手推一下自己走回去"变得迟钝。
- 等效的"驻车刚度"：`kp_pos · kd = 15 × 2 = 30 N·m/rad ≈ 0.52 N·m/deg`。对比腿的 80 N·m/rad，轮子驻车只有腿刚度的 38%，是**软**的。
- 力矩上限校核：误差到钳位值 0.3 rad 时外环要 4.5 rad/s，被 `omega_max` 截到 3 rad/s，`τ = 2 × 3 = 6 N·m`，只有轮子力矩上限 21.6 N·m 的 28%。所以驻车全程不会出现"憋着劲突然一下"的情况。
- 稳态停位偏差：平衡时每轮需要 0.24 rad/s 的指令来对消载荷，`e = 0.24 / 15 = 0.016 rad ≈ 1.6 mm`。也就是说它把蠕变从"每秒几毫米"变成了"总共 1.6 mm"，而不是硬顶在零点。

如果确实想更软：**继续降 `wheel_park_kp`**（15 → 8 会让响应时间常数变 125 ms、等效刚度降到 16 N·m/rad、停位偏差升到 3 mm），而不是去动 `kd`。动 `kd` 会同时改变行驶时的速度跟踪特性，属于另一件事。

### 4.4 三个边界条件

1. **轮角不 wrap。** 轮关节是 `continuous`，转 2π 车身走 `2π × 0.09 = 0.565 m`。用 `wrap_to_pi` 会把"再往前转一圈"误判成"往回转一圈"，驻车环会直接把车拽回去。所以误差用**未缠绕的原始值**加钳位，`q_hold` 只在两个时刻重锚：
   - 指令**刚变成零的上升沿**（"就停在现在这里"，不是走回上次站的地方）；
   - **回合重置**（`episode_length_buf <= 1`）。
2. **拖动/打滑时不抵抗。** `|q_hold − q| > 0.3 rad` 说明轮子被拖着走了（或整机打滑），此时直接把 `q_hold` 重锚到当前角度，而不是命令它转回来——否则一次外力会把轮子顶到 `ω_max` 连续 40 ms，反而产生一次可见的倒退。
3. **零指令下策略的轮动作没有权限。** 这是刻意的：零指令本来就只有"别动"一个正确答案，不需要策略花容量去学它。替换发生在 action term 之前，**并且替换值会写回动作向量**，所以 `last_action`（观测）和 `action_rate`（奖励）看到的是真正下发的命令，策略不会在一个"输出被悄悄改写"的世界里学出一个不存在的因果。

### 4.5 触发条件

```
|vx*| ≤ 1e-3  ∧  |vy*| ≤ 1e-3  ∧  |ωz*| ≤ 1e-3
```

三个轴**同时**为零才触发，判据直接读命令缓冲（`base_velocity.vel_command_b[:, :3]`），与奖励里 `wheel_speed` 的门控**同一处判据**，不设滞回、不设 0.03/0.07 的死区。

- 为什么不用滞回：滞回需要记忆，而记忆会在"指令刚给到 0.001 m/s"时产生一个状态机；而 `1e-3` 已经是浮点噪声级别，混合采样给出的零指令是**精确的 0**（`MixedVelocityCommand` 在零分支里写的就是 0）。
- 为什么和奖励共用一个判据：如果奖励认为"站着"而驻车环认为"在走"，训练信号就会与物理行为脱节——这比多一个判据更糟。

### 4.6 它不做什么

- 不切增益（执行器永远是速度伺服），所以 0 → 0.3 m/s 的切换**没有力矩阶跃**，也没有两套动作语义。
- 不参与奖励计算（`wheel_speed` 只看实际轮速，不看外环输出的期望值）。
- 不改变行驶时的任何行为：非零指令下 `_park_wheels` 直接返回原动作，一次张量拷贝都不做。
- 不接管"被推之后回到原位置"这个能力——那是机身层面的事（需要 `hold` 位置项 + 外环），不在这一版。

## 5. 与奖励的关系

轮子相关只有一项带门控：

| 项 | 形式 | 门控 | 作用 |
| --- | --- | --- | --- |
| `wheel_speed` | `1[cmd=0] · mean₄((q̇_w / 2)²) × (−0.2)` | 严格零指令 | 压住"腿撑住底盘、轮子空转" |

注意它罚的是**实际转速**，与驻车环无关：驻车环让轮子真的不转之后，这一项自然归零。两者是互补的——奖励给"别转"的动机，驻车环给"能停住"的物理手段。

## 6. 搬到硬件上

| 仿真里的东西 | 硬件上的对应 |
| --- | --- |
| `q̇_eq = F_bias/(4·kd)` 的蠕变 | 真实轮组有轴承/滚阻和减速箱粘性，蠕变通常比仿真小；但**零速伺服依然不等于刹车** |
| `kd = 2` 的粘性 | 速度环的阻尼增益，不是机械刹车 |
| 驻车位置外环 | 位置模式下的"锁轴"（很多轮毂电机的自带驻车功能就是它） |
| 连续无界的 `joint_pos` | 增量式编码器 → 多圈计数器（float32 在 440 rad 处分辨率 3e-5 rad，够用） |
| 不 wrap 的误差 | 同样：误差用多圈差值，不要先取模 |

部署检查清单：

1. 增量编码器的**多圈计数**方向与 URDF 正方向一致（否则驻车会把车拽着走）；
2. 位置外环的输出仍要过速度环与力矩限幅，不要直接输出电流；
3. `ω_max` 按真实轮组减速比与电机额定转速重算（0.27 m/s 是示例值）；
4. 上电时的 `q_hold` 取当前角度，不要取里程计原点。

## 7. 调试清单

先分清这几行诊断输出**分别由谁打印**：

| 输出 | 由谁打印 | 内容 |
| --- | --- | --- |
| `[health] ...` | `train.py`（训练时） | `max|qdot|`、`max|v|`、`z` 区间、`|v_xy|`、`standing`、`rew`、`neg`、`fall_rew`、`timeout_rew` |
| `[terms] ...` | `train.py`（`--per_term_every`，默认 200 轮） | 每个奖励项的每步贡献与回合累计 |
| `[status] ...` | `play.py`（`--status_every`，默认 50 步 = 1 s） | 指令缓冲、`|v_xy|`、`wz`、高度、倾角、`qdot_leg`、`qdot_wheel`、`standing` |
| 表格 | `eval.py` | 12 组固定指令的 RMSE / 倾角 / 摔倒率 / `drift` |

`play` 里"给了指令但不动"，先看 `[status]` 的三个数：`standing=1.00` 说明指令根本没进缓冲（此时驻车环也还锁着轮子）；`standing=0.00` 但 `|v_xy|` 仍 ≈0、而 `qdot_wheel` 很大 `qdot_leg` 很小时，是轮子在转但没抓地（腿把机身撑住了）。

### 7.1 谁拥有指令

`play` 与 `eval` 里指令归**人**（或测试表），不归命令采样器。命令项本身会在两处自行动手：每隔 `resampling_time_range` 秒、以及**每次回合重置**（摔倒、20 s 超时）时重采样一次。它的写入发生在我们写入之后，于是表现成"命令行给了 2.0 m/s，机器人却在原地站着"——尤其阶段 1 的采样范围是全零，重采样就等于把指令清零。

所以两边都调 `isaaclab_m20.tasks.commands.freeze_command_resampling(term)`：改 `cfg.resampling_time_range`、改它缓存下来的 `_resampling_time_range`、把 `time_left` 倒计时填满，最后把 `_resample_command` 换成空函数（这一条同时覆盖重置路径）。改成空函数后 `is_standing_env` 保持初值 False 也无所谓——奖励和驻车环读的都是命令缓冲，不是这个标志。

另加三道自证：启动时打印 `[INFO] Policy obs: 56 dims, command slice obs[37:40] = [...]`（策略真正看到的指令，非零才算链路通）；`[status]` 里同时给出 `cmd=` 与 `obs_cmd=`，两者一致说明观测没有另行缩放或取错项；`play` 写完指令后立刻打一行 `[INFO] write check: sent [...], buffer now [...]`，若这一行就已经不等，说明写入根本没落到缓冲区（属性不是那个张量），而不是被谁覆盖。

还有一层容易被忽略的顺序：**回合重置发生在 `env.step` 内部**，即"先执行动作 → 再重采样命令 → 再构建观测"。所以外部写入即使用 `_resample_command` 之外的方式，也会被重置路径挡在观测之前。为此 `M20VelocityEnv` 提供 `set_command(vx, vy, wz)`：把指令存成 `command_override`，在 `step()` 开头与每次 `_reset_idx()` 之后各写回一次，`play`/`eval` 优先走这条路。它同时保证驻车环看到的就是这条指令。

| 现象 | 先看 | 处理 |
| --- | --- | --- |
| 零指令还在溜 | `eval` 第 9 行 `mean_speed` / `drift`；`[health] |v_xy|` | 先确认 `standing=1.00`；再确认驻车环没有打 WARN 自动禁用；仍溜就 `wheel_park_kp` 15 → 25 |
| 起步/停车顿挫 | `play` 里 `--cmd_vx` 0 ↔ 0.3 | 降 `wheel_park_kp`（15 → 8），不要动 `kd` |
| 轮子持续空转 | `Episode_Reward/wheel_speed` 大而 `|v_xy|` 小 | 腿撑住底盘、轮子悬空——这是姿态问题（`joint_deviation` / `base_height`），不是驻车环 |
| 驻车把车拽回去 | 日志 `[WARN] ... parking brake`；`q_hold` 是否在指令归零时重锚 | 检查误差是否被 wrap（不该出现）与 `error_clamp` 是否太小 |
| 位置环"嗡嗡" | 轮速 `|qdot|` 高频抖动 | `kp_pos` 与外环带宽太高：比值应保持 ≥ 20（`kp_pos ≤ 700/20 = 35`） |
